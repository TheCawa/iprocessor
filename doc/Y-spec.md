# Спецификация языка Y (i80148)

**Версия:** 0.8 — полноценная куча, расширенный `printf` и автоматическая линковка  
**Целевая архитектура:** i80148 (32-бит flat, big-endian)  
**Компилятор:** `i80148/tools/Y/ycc.py` (Python 3), генерация CASM148-ассемблера  
**Расширение исходников:** `.y`

---

## 1. Общая концепция

Y — компилируемый C-подобный язык. Он компилируется в ассемблер i80148 (`CASM148.py`), а затем в плоский бинарник или объектный файл. Главная цель MVP — дать возможность писать программы уровня сложности CBASIC, но с нормальными функциями, указателями, локальными переменными на стеке и рекурсией.

## 3. Типы данных

### 3.1 Базовые типы

| Тип | Размер | Знаковость по умолчанию |
|---|---|---|
| `char` | 1 байт | **unsigned** (как в CBASIC/CASM байт) |
| `unsigned char` | 1 байт | unsigned |
| `signed char` | 1 байт | signed |
| `short` | 2 байта | signed |
| `unsigned short` | 2 байта | unsigned |
| `int` | 4 байта | signed |
| `unsigned int` | 4 байта | unsigned |
| `long` | 4 байта | signed |
| `unsigned long` | 4 байта | unsigned |
| `void` | — | — |

### 3.2 Производные типы

- **Указатель:** `int *p;`, `char **pp;`
- **Массив:** `int arr[10];` — размер константа времени компиляции.
- **Структура:**
  ```c
  struct Point {
      int x;
      int y;
  };
  ```
  - Поля упакованы без выравнивания (packed).
  - Доступ: `p.x`, `ptr->x`.

### 3.3 Приведения

Допустимы явные приведения: `(int *)p`, `(unsigned char)c`. Неявные приведения между арифметическими типами и указателями выполняются по правилам C (integer promotion до `int`).

## 4. Объявления

### 4.1 Глобальные переменные

```c
int g_counter = 0;
char message[32];
char *greeting = "Hello";
extern int disk_status;  // определена в CASM-модуле
```

- Инициализированные попадают в `.data`.
- Неинициализированные — в `.bss`.
- Указатели могут быть инициализированы строковыми литералами: `char *s = "..."`.
- `static` даёт внутреннее связывание: символ не экспортируется через `.global`.
- `extern` — ссылка на символ из другого модуля (генерируется `.extern`).
- По умолчанию глобальные функции и переменные имеют внешнее связывание.
- `extern` без инициализатора — чистое объявление, не резервирует память.

### 4.2 Локальные переменные

```c
int foo(int n) {
    int local;
    char buf[16];
    ...
}
```

Размещаются на стеке внутри функции. Поддерживаются автоматические массивы.

### 4.3 Функции

```c
int add(int a, int b);

int add(int a, int b) {
    return a + b;
}
```

- Параметры и локальные переменные — на стеке.
- `main` возвращает `int`.
- Пустой список параметров `()` означает **нет параметров**.

## 7. ABI i80148 (Y calling convention)

### 7.1 Передача аргументов

- Аргументы кладутся на стек **справа налево** инструкциями `PUSH`.
- Стек i80148 растёт **вверх** (адреса увеличиваются), поэтому:
  - первый аргумент доступен по `[BP-8]`;
  - второй аргумент — `[BP-12]`;
  - третий аргумент — `[BP-16]`.
- Caller чистит стек после `CALL` инструкцией `ADD.DW SP, <размер аргументов>`.

### 7.2 Возвращаемое значение

| Размер | Регистр |
|---|---|
| 1 байт | `XL1` |
| 2 байта | `X1` |
| 4 байта | `EX1` |

Большие структуры возвращаются через скрытый указатель (решается позже, в MVP — не больше 4 байт).

### 7.3 Стековый фрейм

```asm
foo:
    PUSH BP
    COPY BP, SP
    ADD.DW SP, <размер локалов>   ; стек растёт вверх
    ...
    COPY SP, BP
    POP BP
    RET
```

- Локальные переменные располагаются по `[BP+4]`, `[BP+8]` и т.д.
- Аргументы располагаются по `[BP-8]`, `[BP-12]` и т.д.

### 7.4 Регистры

- **Caller-saved:** `EX2..EX7`, `A0..A7`, `X2..X7`, `XL2..XL7`.
- **Callee-saved:** `BP`, `SP`. При необходимости `IX`, `IY`.
- `R0` — всегда ноль (если используется в коде).

## 8. Модель памяти

```
0x00000000 .. 0x0000FFFF   BIOS ROM (не трогаем)
0x00010000 .. 0x0001FFFF   CMOS
0x00020000 .. 0x0002FFFF   MMIO
0x00030000 .. 0x0003FFFF   Device calls
0x00040000 .. 0x0004FFFF   BIOS RAM
0x00050000 .. 0x0005FFFF   VRAM window
0x00060000 .. ...          .text / .data / .bss / heap
...                        стек растёт вверх к 0x000FFF00
```

- `.org 0x00060000` для user-программ.
- Стек инициализируется в сгенерированном `_start` значением `0x000FFF00`.
- Куча начинается сразу после `.data` (глобальные переменные и строковые литералы) и растёт вверх к стеку.

```c

#define MAX_SIZE 256
#define VERSION 0x0001

#ifdef DEBUG
    ...
#endif

```

- `#include` — текстовая вставка с поиском относительно исходника и `i80148/tools/Y/stdlib/`.

- Include guards защищают от повторного включения.

## 10. Стандартная библиотека (MVP)

### 10.1 Runtime-библиотека

Runtime реализован в `i80148/tools/Y/stdlib/runtime.asm` и автоматически линкуется с каждой Y-программой. Заголовки стандартной библиотеки находятся в `i80148/tools/Y/stdlib/` (`yio.h`, `ystring.h`, `ystdlib.h`, `ydisk.h`).

Startup-файлы:
- `ycrt0.asm` — startup для плоского режима (встраивается `ycc`).
- `crt0_y.asm` — startup для объектного режима (линкуется как отдельный объектник).

Доступные функции:

| Группа | Функции |
|---|---|
| Ввод-вывод | `putchar`, `getchar`, `puts`, `gets`, `print_int`, `print_uint`, `print_hex`, `print_ptr`, `printf` |
| Строки | `strlen`, `strcpy`, `strncpy`, `memcpy`, `memset`, `memcmp` |
| Стандартная | `malloc`, `free`, `atoi`, `abs`, `exit` |
| Диск | `disk_read(lba, buf, count)`, `disk_write(lba, buf, count)` |

### 10.2 `printf` — поддерживаемые спецификаторы

Текущая реализация: `%d %u %x %p %s %c %%`.

- `%d` — знаковое десятичное целое.
- `%u` — беззнаковое десятичное целое.
- `%x` — беззнаковое шестнадцатеричное целое (нижний регистр, без ведущих нулей).
- `%p` — указатель в форме `0xXXXXXXXX`.
- `%s` — строка, оканчивающаяся нулём.
- `%c` — символ.
- `%%` — литеральный `%`.

### 10.3 Куча

- Реализована в `stdlib/runtime.asm`.
- Используется **explicit free list** с метками границ (boundary tags).
- `malloc` ищет первый подходящий свободный блок, при необходимости делит его.
- Если свободного блока нет, память запрашивается у bump-области за `.data`.
- `free` помечает блок свободным, коалесцирует его с соседними свободными блоками и вставляет в free list.
- Куча инициализируется в сгенерированном коде: `_heap_start` размещается сразу после глобальных переменных и строковых литералов.

## 11. Линковка

Компилятор Y поддерживает три режима:

1. **Плоский бинарник** — `ycc file.y -o file.bin`; runtime встраивается автоматически.
2. **Многофайловый бинарник** — `ycc main.y helper.y ... -o program.bin`; `ycc` сам компилирует каждый `.y` в объектник, пересобирает `crt0_y.o`/`runtime.o` при необходимости и вызывает `LINK148.py`.
3. **Объектный режим** — `ycc -c file.y -o file.o`; генерируются `.global`/`.extern`, а затем линковка через `LINK148.py` с `crt0_y.o`, `runtime.o` и CASM-объектниками.

### `extern`/`static`

```c
// main.y
extern int magic_value;          // из CASM-модуля
static int helper(void) { ... }  // только для этого модуля

int main(void) {
    print_string("from Y\n");
    return magic_value;
}
```

```asm
; helper.asm
.text
.global print_string
.global magic_value

.data
magic_value: .DD 42

.text
print_string:
    ...
    RET
```

### Автоматическая многофайловая сборка

```bash
python i80148/tools/Y/ycc.py demos/30_link/main.y demos/30_link/helper.y \
    -o demos/30_link/30_link.bin
```

`ycc` сам скомпилирует каждый `.y` в `.o`, обновит `crt0_y.o`/`runtime.o` при необходимости и вызовет `LINK148.py`.

### Ручная сборка объектного режима (Y + CASM)

```bash
python i80148/tools/Y/ycc.py -c demos/30_link/main.y -o demos/30_link/main.o
python i80148/tools/CASM/CASM148.py -c i80148/tools/Y/stdlib/crt0_y.asm -o i80148/tools/Y/stdlib/crt0_y.o
python i80148/tools/CASM/CASM148.py -c i80148/tools/Y/stdlib/runtime.asm -o i80148/tools/Y/stdlib/runtime.o
python i80148/tools/CASM/CASM148.py -c demos/30_link/helper.asm -o demos/30_link/helper.o
python i80148/tools/LINK/LINK148.py \
    i80148/tools/Y/stdlib/crt0_y.o \
    i80148/tools/Y/stdlib/runtime.o \
    demos/30_link/main.o \
    demos/30_link/helper.o \
    -o demos/30_link/30_link.bin \
    --base 0x00060000 --entry _start
```

## 12. Тестирование и запуск

Скомпилировать программу:

```bash
python i80148/tools/Y/ycc.py program.y -o program.bin
```

Запустить в консольном эмуляторе:

```bash
emulator/dist/console_emu.exe program.bin 0x00060000
```

Чтобы увидеть вывод `putchar`/`puts`/`printf` после остановки CPU:

```bash
emulator/dist/console_emu.exe --dump-term program.bin 0x00060000
```

Интеграционные тесты Y (проверяют возвращаемое значение `main` через регистр `EX1`):

```bash
python i80148/tools/Y/tests/integration/test_demos.py
```

## 13. Что пока не реализовано

- `float` / `double`
- `long long` / 64-битные типы
- `union`
- Функции-указатели
- Inline-assembly (хотя синтаксис `asm { ... }` зарезервирован)
- Возврат структур по значению и передача структур по значению
- Поддержка i8046
- Сложные оптимизации
